# v1.2 前端原型与确认范围

## 已确认方案

- 应用首版采用配置式编辑，提供智能客服、报告撰写两个模板。
- 元数据采用通用字段，并允许按知识库扩展；原文缺失的事实不猜测。
- 同一文档默认检索当前有效版本，保留历史；新索引构建成功后再切换。
- 继续只做桌面 Web。先交付可操作的前端原型，确认后再接入后端。

## 本机入口

- 应用中心：http://127.0.0.1:4173/applications
- 导入工作台：http://127.0.0.1:4173/ingestion
- 知识库列表与详情均增加“智能导入原型”入口。详情入口的导入方案按知识库独立保存。

构建：在 frontend 目录运行 `npm run build:preview`，然后 `npm run preview -- --port 4173`。原型配置保存在浏览器 `zhixu-v12-*` 键中，与现有服务端数据分开。

## 建议评审顺序

1. 导入工作台：选择示例资料 → 元数据 → 查看来源依据、补负责人、添加自定义字段 → 切分预览 → 切换策略与父子检索 → 版本与构建 → 保存方案。
2. 应用中心：创建客服或报告应用 → 基础配置、知识与检索、体验与发布 → 保存草稿 → 发布原型 → 独立使用入口。
3. 报告模板：填写输入字段与任务 → 确认或修改大纲 → 预览示例报告 → Markdown 下载。
4. 切换使用者角色：只能进入已发布且对该角色可见的应用，不能编辑应用或导入方案。

## 交付边界

本轮未修改后端、数据库或线上部署。未调用抽取、语义切分、问答对提取、应用执行模型。所有这些处理结果明确标记为示例。

- 结构、语义、问答对预览使用示例内容；自定义长度、分隔符、正则会在浏览器中展示文本边界。
- 可读取本地 Markdown / TXT（原型限 1 MB）；内容不上传，元数据仍为示例值。
- 发布只生成本地配置快照，保存草稿不影响已发布快照。应用入口和报告输出为交互演示。
- Markdown 示例报告可直接下载；Word 导出显示待后端接入提示。
- 版本关系与生效切换为交互原型，尚不改变真实检索范围。
- 本轮执行 TypeScript / Vite 构建检查，未运行自动化测试套件。

4. 应用、草稿与发布快照、应用会话及日志归属。
5. 客服执行链、报告分章节检索与撰写、实际用量和导出。
