# FastGPT 产品调研与借鉴建议

调研日期：2026-10-26。用途：为专业知识库中台 1.0 提供功能与体验参考。

## 1. 调研范围与证据

本次查阅 FastGPT 官方使用指南、快速上手、搜索方案、模型配置、引用阅读器、权限与版本说明，并通过浏览器查看官方操作截图。未登录 FastGPT 实际租户，未进行付费版本实测。因此，下文的“支持”指官方资料说明；界面观察来自官方截图，不代表已验证全部运行行为。

调研覆盖主要功能域，不将其视为对所有节点、插件、套餐的逐项验收。FastGPT 持续迭代，后续实现以本项目确认的需求为准。

## 2. 成熟产品功能地图

| 功能域 | 官方资料中的主要能力 | 本项目 1.0 建议 |
| --- | --- | --- |
| 知识生命周期 | 文件导入、解析、分块预览、知识入库、数据维护 | 核心范围，必须形成闭环 |
| 检索增强 | 语义/全文/混合检索、重排、问题优化、引用内容上限 | 混合检索和重排进入首版；问题优化可配置 |
| 引用验证 | 引用片段、查看全文和上下文 | 首版支持文件来源、位置及原文查看 |
| 数据组织 | 知识库、集合标签、网站同步及第三方数据源 | 首版采用知识库与文件两级；标签保留简单版本 |
| 对话应用 | 提示词、模型、开场白、关联知识库、调试 | 合并为问答设置与检索测试，无需先搭建应用才能问答 |
| 工作流与 Agent | 可视化编排、工具、技能和自主多步任务 | 作为后续扩展，不进入本次 RAG 闭环 |
| 模型管理 | 模型渠道、多类模型、自定义模型、调用测试 | 首版拆分服务商、模型和用途绑定 |
| 运行与评测 | 对话记录、模型用量、运行日志看板、应用评测 | 首版做对话日志、分阶段耗时、Token 和失败定位 |
| 发布与集成 | 分享、API、嵌入及第三方渠道 | 首版提供内部 Web 入口，暂缓渠道集成 |
| 团队治理 | 协作、权限、SSO、成员同步 | 首版做三角色体验与知识库可见角色配置 |

## 3. 版本差异

依据[官方版本对比](https://doc.fastgpt.io/zh-CN/guide/version/commercial)，工作流、知识库、多模型配置等属于基础能力；运行日志看板、应用评测、图片知识库、索引增强、网站同步、文件级权限等存在商业版/云服务版差异，不能假设社区版全部具备。

[文件级权限文档](https://doc.fastgpt.io/zh-CN/guide/dataset/collection_permission)明确说明该能力为商业版特有功能。本项目计划自主实现知识库级的可见角色配置，不复制其授权体系，也不将自由切换角色描述为身份认证。

## 5. 本项目的信息架构建议

全局导航：工作台、知识库、在线对话、任务中心、日志监测、模型服务。

知识库详情页签：文件、知识片段、检索测试、问答设置、权限与配置。角色切换放在顶部固定位置，显示当前角色；不使用头像冒充真实账号。

使用者默认进入在线对话；知识库管理人员默认进入知识库；管理员默认进入工作台。导航按角色展示，知识库列表、检索、下载和引用由后端执行相同范围校验。

视觉方向建议：浅灰背景、白色内容区、蓝紫主色、明确的状态标签；正文 14–16px，桌面优先，表格与文档内容留足阅读宽度。颜色不能成为区分成功/失败的唯一手段。

## 6. 文案与异常体验建议

| 场景 | 建议文案/交互 |
| --- | --- |
| 首次进入 | “创建知识库，导入资料后即可开始问答。”并提供创建入口 |
| 缺少模型 | “请先配置并测试向量模型。”提供直达模型配置入口 |
| 开始构建 | 显示文件数、解析方式和可能发生的云端调用，再由用户点击“开始构建” |
| 处理状态 | 排队中、解析中、待确认、向量化中、已就绪、部分失败、失败 |
| 解析失败 | 显示失败文件、失败步骤、可操作原因，提供“重试此文件” |
| 没有召回依据 | “当前知识库中未找到足够依据。请补充资料或换一种问法。” |
| 引用 | “员工手册.pdf · 第 12 页”，点击查看对应原文 |
| 模型测试 | 分别显示对话/向量/重排测试结果，不能用一个成功标签代表全部能力 |
| 用量未知 | “服务商未返回用量”，不显示 0 造成误解 |

这些文案为本项目拟定，目的在于让用户知道当前状态、失败原因与下一步操作。

## 7. 结论

建议借鉴 FastGPT 的知识处理步骤、检索测试和引用验证方式；本项目围绕企业内部资料问答收敛范围。完整范围、选型对比和待确认项见《02-知识库中台1.0方案》。
