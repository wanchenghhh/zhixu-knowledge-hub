# v1.2 元数据、智能切分与应用后端

## 版本内容

### 文档加工

知识库提供处理方案与字段模板，支持文本、多值文本、日期、数字字段。新导入文档自动调用所配置的云端 LLM 提取标题、发布日期、生效日期、版本、主体、负责人，生成关键词与建议问题。事实字段保存原文位置和逐字证据，无依据时为空；人工修正单独标记并留存修改记录。

建议问题除作为元数据展示，还生成辅助向量并关联原文片段；回答仍引用原文。元数据过滤在召回前执行，支持文本/多值字段匹配、日期和数字范围。缺失字段不会被猜测为匹配结果。

### 切分与索引

- 自动结构切分：优先段落与标题边界，表格按行组保留表头。
- 自定义切分：按长度、标题、页、段落、正则；正则执行设超时。
- 语义切分：对较小段落调用 Embedding，依据相邻段落相似度合并。
- 问答对：读取已有“问/答、Q/A”格式，或调用模型提取；提取答案必须能逐字对应原文。
- 父子检索：小片段参与召回，可附带更大原文上下文。

长度参数使用字符数。语义切分、问答对和辅助索引会产生真实云端模型用量，按任务记录。处理进度保存在数据库，可续作；片段更新与向量构建进入队列，成功后切换文件的索引指针，失败保留原索引。

### 版本与历史

同一知识库内可以确认文档组关系，保留每个原始文件、版本号、生效/失效日期和索引。相同标题仅作为关联建议，不自动覆盖。默认检索当前有效版本，在线对话和应用可选择包含历史；回答来源携带版本与日期。

未标注生效日期时按激活顺序参与选择，不把激活日期写成原文事实。未来生效版本到期前不进入默认范围。停用当前版本不会自动复活旧版本。重新构建同一文档保留已确认文档组。

### 应用与报告

配置式客服与报告模板提供独立模型、知识库、提示词、输入字段、结构化元数据过滤、角色范围、历史轮数、TopK、阈值与重排参数。草稿调试是真实调用；保存草稿不改变发布快照。发布、下架、复制均由服务端处理。用户只能使用对其角色与知识库可见的发布版本。

客服支持 SSE、引用、浏览器会话隔离和应用会话历史。应用更新发布版本后需新建对话。

报告执行顺序：提交任务 → LLM 大纲 → 用户编辑/确认 → 逐章节检索与撰写 → 汇总引用。每章保存进度，支持停止与从失败处继续。可导出 Markdown 和 Word（标题、列表、表格）；日志记录应用、发布版本、调用用量及耗时。报告记录与任务中心提供执行进度。

## 运行与迁移

本机：构建 frontend 的 `build:live`，运行 backend 的 `python -m app.migrate`，然后启动 FastAPI。SQLite 已在升级前备份到忽略的 runtime/backups 目录。线上继续使用已有 Neon、私有 Blob 和 Vercel Queues，构建命令自动执行 Alembic。未更换密钥或新建付费资源。

迁移版本 b817cda3 为增量迁移。旧文件可继续检索；需要在智能导入与加工页明确升级，才会重新提取元数据及构建索引。原型浏览器草稿不会被悄悄迁移为正式应用。

## 人工验收步骤

1. 进入知识库 → 智能导入与加工，上传一份含日期、版本与负责人的文档；等待解析抽取。
2. 查看抽取依据，修正字段或扩展本库字段，再检查切分预览。
3. 在四种策略中按资料选择，生成真实预览，确认文档组与版本后构建。
4. 导入新版本关联原组，检查当前有效标记；对话分别选择当前与历史范围。
5. 在应用中心创建客服，绑定知识库、设置角色和过滤条件，保存、调试、发布后使用独立入口。
6. 创建报告应用，提交任务并确认大纲，等待章节完成，查看来源并下载 Word/Markdown。
7. 在任务中心查看文档和报告进度，在日志监测按应用筛选，核对用量和耗时。

图片、扫描 PDF 及增强解析仍需单独配置 DocMind 云端凭证。角色仍按已确认方案自由切换，站点公开免登录。
