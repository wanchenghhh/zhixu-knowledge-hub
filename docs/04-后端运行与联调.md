# 后端运行与联调

适用范围：桌面 Web、企业内部 1.0。本机先验证业务，再使用 Docker Compose 部署内网。当前没有登录；角色可自由切换，接口按所选角色执行可见范围检查，不能把角色选择视为身份认证。

## 技术与运行方式

- React / TypeScript / Ant Design：沿用已确认的桌面原型，接入真实接口。
- FastAPI / SQLAlchemy：参数校验、显式业务接口、加密模型配置、文件与任务持久化。
- LangChain：`Document` → `RecursiveCharacterTextSplitter` → 云端 `Embeddings` → `BaseRetriever` → Rerank → `ChatPromptTemplate | ChatOpenAI` 流式回答。
- 本机使用 SQLite、文件目录和进程内工作线程；PostgreSQL / pgvector、Redis / Celery 是 Compose 的部署配置。本机模式便于无 Docker 环境验证，SQLite 检索会在 CPU 上计算相似度，不能据此推算生产容量。
- PostgreSQL 使用 pgvector 余弦距离与中文分词后的全文检索，RRF 合并候选，再调用所绑定的重排模型。当前向量查询为精确查询，未配置 ANN 索引；不同向量模型分开查询，不能混合向量空间。

## 本机启动

要求 Python 3.12、Node.js 24；无需本地 OCR 或大模型权重。

```bash
cd frontend
npm ci
npm run build
cd ../backend
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock
cp .env.example .env
uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

打开 <http://127.0.0.1:8000>。FastAPI 同源提供前端和 `/api/v1`，API 文档位于 `/docs`。

首次启动创建 `backend/runtime/knowledge.db`、`runtime/files/`、`runtime/.encryption-key`。三类 AIHubMix 配置只是预设，必须自行保存凭证并执行真实连接测试。密钥由后端加密，接口只返回是否已保存；表单再次保存时留空保留原值。不要将密钥提交到 Git，也不要只备份数据库而丢失主密钥。

前端修改后重新运行 `npm run build`，刷新 8000 页面。单独运行 Vite 原型预览（4173）仍为演示入口，不连接后端业务；真实验收请使用 8000。服务端代码修改后需要重启 Uvicorn，已有数据会保留。

## 模型配置

| 服务商 | Base URL | 能力 |
| --- | --- | --- |
| AIHubMix | `https://aihubmix.com/v1` | LLM、Embedding、Rerank 分别配置 |
| OpenRouter | `https://openrouter.ai/api/v1` | LLM、Embedding、Rerank 分别配置 |
| 通义百炼（中国内地） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | LLM / Embedding 使用兼容接口；Rerank 自动转向百炼原生接口 |

模型 ID、区域、维度与权限须以账户实际支持为准。三类模型独立测试，不把“保存成功”当成“模型可用”。已绑定知识库的向量模型禁止直接更换模型 ID、维度或接口地址；新增配置后在知识库中切换，会创建重建任务，全部成功后才切换索引。失败继续使用旧索引。

网络请求直接使用所配置的 HTTPS 服务地址，不继承进程中可能影响鉴权的代理环境变量。若内网只能通过企业代理访问云端，应在实际部署环境增加显式代理配置后再联调。

接口依据：[OpenRouter RAG 接口](https://openrouter.ai/docs/guides/evaluate-and-optimize/rag)、[OpenRouter Rerank](https://openrouter.ai/docs/api/api-reference/rerank/create-rerank)、[阿里云 DocMind](https://help.aliyun.com/zh/document-mind/developer-reference/docstructure)。

## 导入、构建和问答

1. 模型服务：保存并分别测试三类模型。
2. 新建知识库：绑定向量模型；问答设置可选择重排模型、Top K、阈值和补充规则。
3. 导入资料：选择文件、分块长度与重叠字符，确认涉及云端调用的费用提示。
4. 解析结束后预览正文和位置；确认构建后才进行云端向量化，任务中心可追踪状态与重试。
5. 已就绪文件参与检索和在线对话；引用可查看提取原文、位置并下载原文件。
6. 日志监测记录问题、回答、引用、LLM Tokens、总耗时、各阶段耗时以及检索模型返回的用量。缺失用量或取消生成时标为“未知”，不估算成实际账单。

限制：单文件 20 MB、PDF 200 页、提取文本 200 万字符，超限需拆分。分块单位是字符，不是 Tokens。检索最多选 10 个知识库，候选最多 40 个，回答上下文限制为 12,000 字符。阈值与模型相关，不能当成统一可信度。

| 格式 | 解析与来源定位 |
| --- | --- |
| Markdown | 本地解析，标题与行号 |
| DOCX | 本地提取段落和表格；嵌入图片调用云端 OCR；本地模式按段落定位，增强模式使用云端页码 |
| DOC | 云端文档解析 |
| PDF | 本地按页提取正文、表格；扫描件或含图片时转云端结构化解析，保留页码 |
| PNG / JPG / JPEG | 云端 OCR，识别文字 |
| XLSX / XLS / CSV | 本地提取单元格文字、表格标题与工作表 / 行号；不做电子表格计算引擎或精确统计查询 |

图片识别仅承诺文字提取。合并单元格、跨页表格和复杂版式需要实际文件验收。PDF 页码为文档物理页序，与页面印刷页码可能不同。

## 云端 OCR

模型服务 → 文档解析 / OCR → 配置阿里云 DocMind 的 AccessKey ID、Secret 并启用，区域为杭州。它使用单独的阿里云凭证，AIHubMix Key 不能替代。调用服务的账号需要开通对应能力与权限。

只通过 SDK 调云端 API，不下载权重。提交前落库标记，获得任务号后持久化，重试优先查询既有任务，避免重复提交。提交结果未知时停止自动重提，需在阿里云核对后删除失败文件再上传。对已返回任务号的云端失败也不会无限重提。

## Docker 内网部署

本机环境未安装 Docker / PostgreSQL / Redis，Compose 配置已准备，尚未在容器环境实跑。正式验收仍需安装 Docker 后完成以下流程。

```bash
cp .env.example .env
# 在 .env 设置 POSTGRES_PASSWORD 和持久的 HUB_ENCRYPTION_KEY。
# 可用 backend/.venv/bin/python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())' 生成主密钥。
docker compose up --build -d
docker compose ps
docker compose logs --tail=100 api worker dispatcher
```

Compose 包含 Nginx、API、Celery Worker、任务调度器、PostgreSQL / pgvector、Redis。启动先通过 Alembic 迁移数据库，再启动 API；worker 和调度器等待 API 健康。默认 Web 仅绑定 `127.0.0.1:8080`，打开 <http://127.0.0.1:8080>。供内网使用时，将端口绑定改为企业服务器内网 IP，并由企业网关提供 HTTPS 和访问控制。

任务存在数据库，Redis 故障后仍可重新分发；工作器通过数据库条件更新认领任务，重复投递不重复执行。定期更新租约、保存已完成文件，恢复时跳过已提交文件。云端调用与数据库无法形成跨系统事务，调用成功但进程在落库前崩溃时，Embedding 仍可能重复计费，不承诺恰好一次。

数据卷包含 `postgres`、`files`、`redis`。备份需要同时保留 PostgreSQL、文件卷和 `.env` 中主密钥。不要执行 `docker compose down -v` 来“重启”，这会删除数据卷。本机 SQLite 数据不会自动迁入 PostgreSQL；本机验证资料可在容器中重新导入并构建。

## 测试与验收边界

```bash
cd backend
.venv/bin/pytest -q
.venv/bin/ruff check app tests migrations
cd ../frontend
npm run build
npm test
```

当前后端 25 项测试、前端 6 项领域测试通过，前端生产构建和后端 Ruff 检查通过；SQLite 迁移及模型差异检查、PostgreSQL 离线建表 SQL 生成通过。

自动测试使用独立临时数据库和 HTTP 契约响应，不使用真实密钥，不把固定响应当成云端验证。当前覆盖权限与浏览器会话隔离、加密与错误脱敏、导入/预览/构建/检索/SSE/日志/下载、Word/PDF/表格、OCR 返回结构与任务复用、分块编辑、重建失败回滚、任务重复投递和断点恢复、未知用量，以及 OpenRouter / 通义接口契约。停止生成保留部分正文和已出现的有效引用，用量未知；引用文件停用后隐藏对应历史回答。

2026-10-26 已真实验证 AIHubMix 的 `text-embedding-v4`（1024 维）、`gte-rerank-v2`、`qwen-plus`：四份虚构示例解析入库，查询向量化、重排、流式回答、有效引用、原文件下载和实际用量记录通过。一份验收回答返回 220 LLM Tokens、耗时 4.029 秒；该数字只是本次样例，不是性能承诺。

仍需在相应环境验证：真实 DocMind 图片 / 扫描件 / 复杂表格、OpenRouter / 通义真实账户、Docker + PostgreSQL + Redis 组合、10 路对话压力与大规模知识库。SQLite 自动测试与 PostgreSQL 离线迁移 SQL 检查不能替代这些验收。

状态接口返回最近 1,000 条日志、500 条任务、200 个当前浏览器 / 角色的会话。日志保留期默认 90 天，启动时清理；当前 CSV 导出范围是页面已加载与筛选后的记录。尚无全量分页审计导出或自动滚动归档。

同一会话使用数据库条件更新认领当前轮次，生成中再次发送返回 409，避免多标签页覆盖历史。正常完成或取消会释放占用；服务异常退出后，该会话的占用最多保留 1 小时，期间可以发起新对话。不要同时启动多个本地线程工作器；Docker 环境使用独立 Celery 工作者。
