# 知序 · 可观测中心功能设计（已确认）

设计日期：2026-10-28。范围：桌面 Web；功能方案已由用户确认。v1.2.4 将交互原型集成至现有网站 /observability；真实观测后端尚未接入，本页不调用模型或新增云服务。

## 1. 目标与现状

围绕四个问题组织信息：发生了什么、在哪一步出错、调用了什么上下文、消耗了多少资源。

已核对代码：Job 有阶段、状态、错误、用量；ApplicationRun 有报告阶段与调用记录；QueryLog 有问答、来源、耗时、模型和部分调用用量。现有数据不足以还原完整调用树，也没有通用 Skill 执行记录、完整价格账本或 Harness 事件采集。历史数据只能展示已存在字段，新增字段显示“未采集”，不伪造历史链路。

## 2. 入口与信息架构

“管理与监测”下保留任务中心、模型服务，将“日志监测”升级为“可观测中心”。沿用藏蓝商务配色。中心内六个页签：总览、知识库构建、Agent 运行、对话日志、用量与费用、异常事件。后续设置放在右上角“采集设置”，不新增一级导航。

- 任务中心：排队、停止、重试、续跑等操作；可跳转观察完整链路。
- 可观测中心：查询、定位、分析；操作按钮跳回对应业务流程。首版不从日志一键重放模型或工具，避免意外执行和重复消费。
- 知识库详情增加“构建记录”入口；应用详情增加“运行记录”；对话单轮增加“查看运行详情”。进入时带上对象与版本筛选。
- 页面筛选：时间范围（默认近24小时）、环境、应用/知识库、状态、服务商/模型、Trace ID、关键词；金额/耗时/Token 范围放在高级筛选。筛选随链接保存；后端分页、聚合全量授权范围，不以当前页或最近1000条计算总览。

## 3. 六个视图

| 视图 | 核心内容 | 主要交互 |
|---|---|---|
| 总览 | 根运行次数、执行失败率、P50/P95耗时、已知Token、估算费用、未知用量/未定价覆盖率；趋势、慢调用、失败Top、费用归因 | 点击指标进入带筛选的明细；显示时间、环境、数据覆盖率 |
| 知识库构建 | 文件/版本、构建批次、触发方式、进度、排队/执行时长、失败阶段、模型调用与费用 | 展开逐文件链路；查看页码/片段/索引批次与当前生效索引；跳转任务中心 |
| Agent 运行 | 应用和发布版本、任务摘要、状态、轮数、模型/工具/Skill调用数、耗时、Token、费用、异常数 | 打开调用树/时间线，选择任意节点查看详情；支持按工具/Skill名过滤 |
| 对话日志 | 会话与单轮两层；输入、回答、检索引用、模型、首Token时间、总耗时、Token、执行结果及反馈 | 查看单轮Trace与上下轮；按应用版本、来源文档版本与检索过滤条件追溯 |
| 用量与费用 | 按日、应用、知识库、模型、服务商、调用类型归因；输入/输出/缓存Token；OCR页数、Rerank计量；估算与实际分别显示 | 费用明细下钻到叶子调用；查看价格快照；导出当前授权筛选结果 |
| 异常事件 | 错误/警告、分类、首次/最近发生、次数、影响运行数、关联节点 | 按错误指纹聚合；打开原始事件、定位节点；标记待处理/已知/已解决（有处理记录） |

总览失败率以已结束根运行为分母，排除排队、运行中、等待确认；取消单列。成功恢复的子调用重试不算根运行失败。无依据回答、低相关度、用户差评属于质量信号，不等于执行失败，不把“回答有引用”命名为准确率。首版不自动用额外模型评估回答质量。

## 4. 统一运行详情（核心页面）

完整详情页使用三栏：左侧调用树（约280px），中间节点详情，右侧运行摘要（约260px）。支持切换瀑布时间线，呈现并行和等待。列表点击可先开宽抽屉，再全屏。所有状态同时有文字与图标。

顶部：任务/输入摘要、Trace ID、所属应用/知识库、版本、状态、开始时间、总耗时、已知Token、费用口径。状态包括排队中、运行中、等待确认、成功、部分成功、失败、已取消、已超时、已跳过；运行状态与内容采集状态分别表达。

节点详情六个页签：
1. 输入/输出：请求参数、返回内容、流式累计文本、格式化/JSON切换、截断提示与完整内容查看权限；二进制附件只展示受控引用。
2. 调用上下文：实际发送消息、系统提示词与模板版本、历史消息范围、检索query/过滤、TopK/重排、引用片段及版本页码、可用工具和Skill版本、模型参数。提供调用前后的上下文差异与压缩/裁剪信息（运行时支持时）。只记录服务实际拥有的消息和公开输出，不声称获取模型隐藏思维链。
3. 用量与费用：单次输入/输出/缓存/推理用量（服务商返回时）、原始usage、计量单位、来源、价格生效版本、币种、估算/实际。用量缺失为未知；工具本身无模型用量显示“不适用”，其子模型调用另列。
4. 事件：开始/结束、流式首响应、重试/退避、路由变化、状态切换、检查点、恢复、取消事件。
5. 异常：安全化错误、分类、原始错误码、可重试性、受限堆栈、根因节点、恢复结果。
6. 元信息：trace/span/parent ID、provider request ID、业务ID、部署版本、attempt、队列投递ID、关联运行、配置快照。

Skill区别于普通工具：Skill是可版本化的指令/资源包，工具是实际执行动作。记录 Skill 名称、版本/内容哈希、加载来源、激活原因（显式选择/规则/模型公开返回）、加载/执行/完成状态、资源读取；Skill内部模型和工具调用作为子节点。只加载未执行必须标注“已加载”。当前运行器没有Skill接口，首版先提供采集协议与空态，只有实际接入后才显示真实记录，不能从提示词猜测调用。

## 5. 三条典型链路

- 构建：上传/存储 → 文档解析/OCR → 元数据抽取 → 切分预览/定稿 → 文本/建议问题Embedding → 索引写入 → 生效指针切换。确定性处理使用pipeline节点，只有真实Agent才标为Agent。按文件建立子树，失败保留中间状态；记录页数、表格数、片段数、失败页、索引代次。
- 对话：输入校验 → 查询改写（如有）→ 权限/版本过滤 → 查询Embedding → 混合召回 → Rerank → 上下文组装 → LLM流式回答 → 引用校验 → 保存。逐节点耗时和候选数可查；召回/重排前后分数分别记录，不跨算法直接比较。
- 报告/Agent：任务校验 → Skill加载（如真实存在）→ 规划/大纲 → 等待用户确认 → 分章节检索/工具/LLM → 汇总 → 导出。区分等待时长和活动执行时长；并行节点耗时不能简单相加为总耗时。

一个用户对话轮/构建批次/报告任务对应一个逻辑根Trace。一个会话包含多个Trace。队列跨投递沿用根Trace并新增attempt节点；恢复不重复归账。独立重新运行创建新Trace，用linked_trace_id关联原任务。

## 6. Harness异常目录与边界

Harness指围绕Agent的执行环境、循环控制、上下文和工具调度。首版记录：
- 模型：401/403、429、超时、额度不足、路由失败、输出截断、结构化输出解析/校验失败。
- 工具/Skill：不存在、版本不匹配、加载失败、参数校验失败、权限拒绝、超时、执行异常、无有效结果。
- 控制：最大轮数、重复调用/疑似死循环、上下文超长、预算/截止时间触达、压缩失败、取消、确认等待超时。
- 持久执行：队列延迟、租约到期、重复投递、检查点失败、恢复失败、索引/文件存储失败。
- 采集自身：事件丢失、Trace不完整、usage缺失、超时未闭合、敏感信息脱敏失败。采集不完整与业务失败分别统计。

只有已有明确运行器信号才能标“已触发”，推断风险显示“疑似”；没有预算/轮数拦截机制时不展示为已启用。预算告警首版站内提示；真正的费用硬上限需要预算预留/并发记账与在途请求策略，单独实施，不能凭估算余额承诺不超支。

## 7. 用量与费用规则

- 覆盖所有实际模型/外部服务调用：构建、元数据、建议问题、查询Embedding、Rerank、对话、报告、OCR；失败与重试也可能有消耗。
- 基础事实是每次物理请求的usage/计量与attempt；只对叶子计费记录汇总，父节点为展示聚合，防止重复计算。队列重复投递用事件ID幂等，真正再次请求产生新计量记录。
- 用量来源：服务商返回 / 本地估算 / 未知，分开统计；缓存命中和推理Token按服务商定义表达，不在total中二次叠加。
- 金额来源：服务商返回实际费用 / 账单对账费用 / 用量×价格估算 / 未定价；已对账实际替代该请求估算，不能两者相加。模型返回usage不等于账单。
- 服务商、模型、路由后真实模型、价格版本、计量单位、输入/输出/缓存价格、币种、免费额度使用证据均留快照。无法识别实际路由或单价时保留未定价。
- 免费模型仅在本次路由/价格有依据时标免费；通义试用有额度与期限，不默认每次消费为0。没有账单能力时显示“未接入账单对账”，不伪装已扣费。
- USD/CNY分币种合计；如提供折算，必须显示汇率来源、日期和仅供估算。无价、未知、部分覆盖不按0填充。
- 存储/队列/数据库等基础设施账单首版不归因到单次Agent；作为未来外部账单项，不混入模型调用费用。

## 8. 采集、存储和访问

推荐首版使用现有LangChain回调 + 通用工具/Skill包装器 + 队列/检索显式埋点，写入现有PostgreSQL，较大正文放现有私有Blob。采用trace/span/event/usage-ledger/price-version数据结构，保留OpenTelemetry映射与导出扩展点。这样不增加外部订阅和部署服务，代价是需要维护埋点、查询和聚合；暂不引入LangSmith SaaS或独立ClickHouse，后续量级增长再评估。

业务权限检查先于正文读取；管理员全局、管理人员仅管理范围、普通使用者仅当前浏览器会话的自身对话简版。无登录自由切换角色仍只是现有体验模式，无法可靠识别真实人员，费用按应用/知识库/浏览器会话归因，不声称按员工计费或建立身份隔离。

API Key、Authorization、Cookie永不入库。默认掩码敏感字段，正文全文采集可配置；受限原文展开和导出有记录，但自由切角色下该记录只用于操作追踪。建议默认脱敏正文7天、运行摘要与计量90天，可由管理员调整；禁止把过期正文的私有Blob链接继续暴露。正文有限长、事件限频、分批写入；采集异常不阻塞业务，错误数量/丢失标记可查。首版默认元信息全量、失败正文全量、成功正文可配置采样；采样只影响正文，不影响计量与运行状态。以上均为待实施设计，不代表现有机制已具备。

## 9. 分期与验收

本轮：功能方案 + 六页签交互预览，全部示例数据有清晰标识，不改线上。

确认后第一期：统一Trace结构；打通现有构建/对话/报告；调用树、输入输出/上下文、单次Token与估算费用、异常定位、筛选与导出；Skill协议和无数据空态；站内异常/预算阈值提示。外部账单自动对账、多Agent跨系统分布式追踪、真实Skill执行器、自动评估、自动重放、外部告警与硬预算控制后续实施。

验收场景：
1. 导入一份文档，逐阶段/逐文件查看原文页码、元数据、片段和索引结果，构建Token可下钻。
2. 完成一次知识问答，从问答进入Trace，看到查询Embedding、Rerank与LLM实际调用，引用可定位版本/页码。
3. 生成报告，区分等待确认和活动耗时，查看章节子节点、上下文和失败恢复attempt。
4. 可控模拟工具错误、模型限流、上下文超限/队列恢复事件，正确分类并定位；只对已接入机制测试，不能伪造未实现的Skill运行。
5. 缺usage或价格时显示未知/未定价；父子汇总及重试不重算；不同币种分开。
6. 默认正文不含密钥；权限过滤、分页聚合和采集丢失提示符合设计。
