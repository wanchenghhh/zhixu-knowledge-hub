# v1.2.5 知识导入、语义切分与应用工具

## 知识库导入

知识库新建后直接进入“文档导入与知识加工”：选择文件和解析方式、确认元数据、选择切分方式与预览、确认版本并构建。已有知识库的“导入知识”也使用同一流程，原独立“智能导入与加工”入口不再显示。中途离开时知识库仍存在，可从知识库详情继续导入；任务状态保存在任务中心。

智能切分先按标点、换行形成语义单元，再使用该知识库绑定的 Embedding 比较相邻单元的余弦相似度，在阈值与最大长度范围内合并；标题优先与后文保留，页、表格等来源边界保留。长单句仍须遵守最大长度；标题、表格、句子和最大长度等约束可导致边界分割。语义判断会产生额外 Embedding 调用，任务记录调用用量。已有知识索引不会自动更改，重新预览并构建后生效。

百炼公开介绍为先按分句标识符划分段落，再根据语义相关性确定边界，并未公开完整实现细节：https://help.aliyun.com/zh/model-studio/rag-optimization 。本实现参考其公开原理，不承诺与百炼结果一致。

## 应用 Skill 与工具

应用编辑的“Skill 与工具”页签可上传单个 `SKILL.md` 或 ZIP 包，ZIP 应包含一个 Skill 目录及其中的 `SKILL.md`，目录名与 frontmatter 中的 `name` 一致。标准 YAML frontmatter 必须包含 `name` 与 `description`。配套文件可放在 `references/`、`assets/` 等目录，模型按需激活 Skill 并读取 UTF-8 文本资源。包最大 1 MB，最多 60 个文件，总解压大小最多 2 MB；SKILL.md 最多 20000 字符，单资源最多 256 KB。

应用可以选择计算器和当前时间两个内置工具。Skill 指令及文本资源通过工具按需加载，包内脚本保留但不执行，二进制文件保留但不作为文本读取；不包含外部 MCP 服务接入。工具调用依赖模型支持标准 tool calling，最多 5 轮、8 次工具调用。带工具的回答在工具调用完成后返回，常规对话保持流式输出。

Skill 包按内容哈希保存为不可变版本；修改后重新上传并在应用中选择新版本，保存草稿和发布互不影响。应用启用工具或 Skill 后，请确保模型支持 tool calling；日志可查看模型与工具调用名称、状态和服务商返回的 Token。历史对话和已发布应用不自动启用新能力。

## 验收

1. 新建知识库后，选择 Markdown 文档，解析并查看元数据和六种切分方式；智能切分预览中检查标题与正文及不同主题的边界，确认版本并构建。
2. 进入应用中心，编辑客服或报告应用，在“Skill 与工具”上传 ZIP 并选择计算器或当前时间；保存并发布。
3. 在应用中提出需要使用 Skill 配套文档或计算器的问题；到现有对话日志或报告任务中查看调用记录与用量。
4. 切分和工具调用均使用所选云模型，实际效果取决于模型能力及语义阈值。可观测中心的六视图仍为原型，已有真实对话日志与任务记录可用。
